# ScalerMind — Requirements

## Functional Requirements

### Authentication
- FR-001: Users can register with email and password
- FR-002: Users can log in and receive access + refresh tokens
- FR-003: Access tokens expire after 15 minutes; refresh tokens after 30 days
- FR-004: Users can log out (refresh token revoked)
- FR-005: Two roles: learner and admin

### Mentor (AI Chat)
- FR-010: Learner can send a question and receive an AI response
- FR-011: AI response streams token-by-token to the frontend
- FR-012: Responses are grounded in curriculum material via hybrid RAG
- FR-013: Responses include citations referencing source documents
- FR-014: Conversations persist across sessions
- FR-015: Learner can view past conversations
- FR-016: Response style adapts to learner skill level

### Code Review
- FR-020: Learner submits code in C++, Python, or JavaScript
- FR-021: System identifies the programming language
- FR-022: Static analysis runs deterministically (no LLM required for syntax)
- FR-023: Complexity analysis (time + space) is performed
- FR-024: Test cases are generated by LLM (structured JSON)
- FR-025: Tests are executed in an isolated sandbox
- FR-026: Execution failures are analyzed and reported
- FR-027: LLM produces a structured review (bugs, suggestions, complexity, confidence)
- FR-028: Review progress streams to the frontend in real time
- FR-029: Reviews are stored and retrievable

### Analytics (Text-to-SQL)
- FR-030: Learner or admin can ask a natural language question about learning data
- FR-031: System generates SQL from the question
- FR-032: Only SELECT queries are permitted (all others rejected)
- FR-033: Queries run on a read-only database connection with a 5-second timeout
- FR-034: Results are explained in plain English
- FR-035: Generated SQL is logged

### Personalization
- FR-040: Learning events are recorded for every significant interaction
- FR-041: Topic performance scores are computed from events
- FR-042: Learner skill level is derived from performance
- FR-043: Mentor adapts explanation depth based on skill level
- FR-044: Weak areas are surfaced in the learner dashboard

### Evaluation
- FR-050: Evaluation dataset can be loaded with Q&A + expected sources
- FR-051: Evaluation jobs run asynchronously via Celery
- FR-052: Retrieval metrics: Recall@K, Precision@K, MRR, nDCG
- FR-053: Generation metrics: faithfulness, answer correctness, context relevance, citation correctness
- FR-054: Engineering metrics: P50/P95/P99 latency, token usage, cost, error rate
- FR-055: Multiple experiments can be compared (baseline vs hybrid vs reranked)
- FR-056: All metrics come from real experiment runs, never fabricated

### Document Ingestion
- FR-060: CLI tool ingests documents from a directory
- FR-061: Supports PDF and Markdown formats
- FR-062: Ingestion is idempotent (re-running does not create duplicate chunks)
- FR-063: Each chunk has full metadata: document, course, topic, lesson, section, page

## Non-Functional Requirements

### Performance
- NFR-001: Mentor chat time-to-first-byte (TTFB) < 1.5 seconds
- NFR-002: Code review completes within 30 seconds P95
- NFR-003: Database query P95 latency < 100ms
- NFR-004: Analytics query completes within 10 seconds
- NFR-005: Evaluation runs are background jobs and do not block the API

### Security
- NFR-010: No secrets in source code or Docker images
- NFR-011: All passwords hashed with bcrypt (cost factor ≥ 12)
- NFR-012: SQL injection prevented by parameterized queries and sqlparse allowlist
- NFR-013: Code execution sandboxed with CPU, memory, time, and output limits
- NFR-014: Retrieved document content treated as data, not instructions
- NFR-015: Per-user, per-endpoint rate limiting via Redis
- NFR-016: CORS restricted to configured origins

### Reliability
- NFR-020: If LLM API is unavailable, return a graceful error (no 500 with stack trace)
- NFR-021: If vector search fails, fall back to BM25
- NFR-022: If Redis fails, continue serving requests (degrade gracefully)
- NFR-023: If reranker fails, use RRF-ranked results directly
- NFR-024: Hanging code execution killed within timeout + 1 second

### Observability
- NFR-030: Every request has a unique X-Request-ID header
- NFR-031: All requests log: request_id, user_id, endpoint, latency, error
- NFR-032: LLM calls log: model, tokens_prompt, tokens_completion, cost_usd
- NFR-033: No secrets or PII logged in plain text

### Scalability
- NFR-040: API is stateless (horizontally scalable)
- NFR-041: Celery workers are independently scalable
- NFR-042: Database connections pooled (pool_size tuned to workload)

### Developer Experience
- NFR-050: docker compose up starts entire system (all 5 services)
- NFR-051: .env.example documents every required variable
- NFR-052: README covers setup, architecture, and common operations
- NFR-053: CI passes on every commit to main

## Out of Scope (Phase 0)

- Mobile application
- Payment processing
- Video streaming
- Real-time collaborative editing
- Multi-tenant organizations
- Custom LLM fine-tuning
- Kubernetes deployment (AWS ECS only)
